# Vector Databases and ChromaDB Guide

## 1. Fundamentals of Vector Search
Traditional relational and text databases perform keyword lookup (e.g., SQL LIKE queries or BM25 index matching). In contrast, vector databases index dense mathematical vectors generated by neural embedding models. This enables semantic search: finding concepts with similar meaning even if exact keywords differ.

## 2. ChromaDB Persistence and Collections
ChromaDB is an open-source, developer-friendly vector database. In a production RAG application, Chroma is configured in persistent mode:

```python
client = chromadb.PersistentClient(path="data/vector_store")
collection = client.get_or_create_collection(
    name="documents",
    embedding_function=embedding_fn
)
```

When documents are indexed, each chunk is stored with a unique ID, its text content, vector embedding, and key-value metadata dict containing `source` filename.

## 3. Top-K Retrieval Tuning
Retrieval relevance depends heavily on the `top_k` hyperparameter:
- Setting `top_k` too low (e.g., 1) risks omitting vital context required for complex multi-part questions.
- Setting `top_k` too high (e.g., 20) introduces noise, increases LLM prompt context length, and slows inference.
- An optimal balance for document QA is `top_k = 4` with a chunk size of 800 characters and 150 character overlap.
